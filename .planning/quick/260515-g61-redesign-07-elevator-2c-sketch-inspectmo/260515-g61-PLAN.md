## Background

1차 sketch (`260510-c2z`, `elevator-sketch.html`) = list 탭 + 페이지 헤더 / 탭 / 카드.
2A sketch (`260515-4zh`, `evselector-sketch.html`) = EvSelector + EsNodeMap + EsBtn (호기 선택 헬퍼 — 모든 모달 공통).
2B sketch (`260515-bgg`, `fault-modals-sketch.html`) = Fault 흐름 3 모달 — ModalWrap shell + Field + MultiPhotoUpload placeholder + CTA 정책 권위.

이번 2C 는 **입력 모달 2종** — `InspectModal` (점검 기록 입력, 5 항목 토글 + 종합 결과 + 조치 필요) + `RepairNewModal` (수리 기록 입력/수정, 수리 대상 4 옵션 + 홀 층 + 4 단계 사진) 컨테이너 시각화. EvSelector 임베드 영역은 2A 의 시각 패턴, ModalWrap/Field/MultiPhotoUpload/CTA 는 2B 의 시각 패턴 재사용. 본 sketch 의 핵심은 **2 모달의 입력 필드 디자인 + 수리 대상 색 정책 결정**.

Wave 1 TSX 변환 (`260515-3mc`) 토큰 매핑이 권위 (bg-surface-raised / bg-surface-sunken / text-text-primary / text-text-secondary / text-text-tertiary / bg-accent / text-text-on-accent / bg-warning-bg / text-warning / border-warning / bg-safe-bg / text-safe / bg-danger-bg / text-danger / border-default / border-strong).

## 디자인 결정 — 수리 대상 색 = warning 토큰

**결정:** `RepairNewModal` 의 수리 대상 4 옵션 (카 / 홀 / 기계실 / 피트) 및 홀 층 칩은 **warning 토큰** 사용 (선택 시 `bg-warning-bg` + `outline-warning` + `text-warning`).

**이유:**

1. **현 코드 (line 3099-3119) 가 yellow `#eab308` (warning hue) 사용** — "수리 = 작업 진행 / 주의" 의미를 시각적으로 이미 표현. accent (파랑) 로 통일하면 의미 손실.
2. **§6.1 색 의미 분리 강화** — accent 는 "호기 선택" (EvSelector 본체) + "CTA" (저장 버튼) 으로 이미 점유. accent 가 2 의미를 동시에 가지면 시각 혼동 (호기 선택과 수리 부위 선택이 같은 색이 되어 위계 모호). warning 으로 분리하면 "이건 호기가 아닌 수리 단계/부위 선택" 임이 한눈에 명확.
3. **2B 패턴과 일관** — 2B 에서는 fire (호기 고장) / danger (승객 위험) / accent (선택+수리완료 CTA) 3 의미 분리. 2C 에서도 accent (호기 선택+CTA) / warning (수리 대상 부위) 로 의미 단계화. status 색 의미가 5종 (fire/danger/warning/accent/safe) 으로 정리됨.
4. **§6.2 negative rule 적합** — warning 은 "위험 임계치 아닌 카드는 status 색 금지" 룰의 예외 (작업 진행 = 주의 상태 표현). 노란색 자체는 fire (긴급 고장) 보다 약한 단계의 상태색이라 "수리 진행" 에 의미 부합.

**대안 — accent 통일 (기각):** 의미 분리 손실 + 현 코드 yellow 의 의도된 시각 표현 손실 + accent 가 호기 선택과 시각 충돌.

**시각화:** VP2 = 홀 + 층 1F 선택 (warning 색 일관 적용), VP4 = 에스컬 (수리 대상 토글 숨김) 또는 덤웨이터 11호기 (카 선택, 카만 warning). 추가 demo row 로 4 옵션 모두 warning 변종 + 비선택 회색 비교 한눈에 노출.
