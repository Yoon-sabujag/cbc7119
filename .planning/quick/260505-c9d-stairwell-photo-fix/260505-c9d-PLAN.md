# 260505-c9d — 특별피난계단 점검 사진 분배 버그 수정

## Problem

`StairwellModal.handleSave`(InspectionPage.tsx:235-249)에서 한 번 업로드한 `photoKey`를 swCPs 루프 안에서 모든 층 CP의 `onSave` 호출에 동일하게 넘긴다. 결과적으로 DB에는 층마다 별도 record가 저장되지만 photoKey가 똑같이 박혀, 데스크톱 점검 상세 진입 시 모든 층 record가 같은 사진을 표시한다.

## Decision

옵션 A — 사진을 계단실 대표 1개 record에만 attach.
- 우선순위: caution/bad 결과가 있는 층 → 그 중 첫 번째 CP
- 그런 층이 없으면 (전부 normal) → swCPs[0] (첫 층)
- 나머지 층은 photoKey: undefined 로 저장

옵션 B/C(별도 테이블, 층별 사진)는 운영 관찰 모드 + 5월 법정점검 임박으로 보류.

## Out of Scope

같은 batch-save 패턴이 있을 가능성이 있는 다른 모달 (ParkingGateModal / PowerPanelModal / DamperModal / CctvModal) 은 이번 범위 아님. 필요 시 별도 quick 으로.

## Tasks

### Task 1 — handleSave photoKey 분배 로직 변경

**files:**
- cha-bio-safety/src/pages/InspectionPage.tsx (StairwellModal.handleSave, ~lines 235-249)

**action:**
photoKey를 모든 CP가 아닌 1개 대표 CP에만 attach. 대표 선정:

```ts
const photoKey = await photo.upload()
const photoTargetCp =
  swCPs.find(cp => {
    const r = floorResults[cp.id] ?? 'normal'
    return r === 'caution' || r === 'bad'
  }) ?? swCPs[0]
for (const cp of swCPs) {
  const keyForCp = cp.id === photoTargetCp.id ? (photoKey ?? undefined) : undefined
  await onSave(cp.id, floorResults[cp.id] ?? 'normal', memo, keyForCp)
}
```

`memo` 는 종전대로 모든 CP에 동일하게 부여 (현재 동작 유지).

**verify:**
- TypeScript 타입체크 (`npm run build` 또는 vite typecheck) 통과
- 변경된 함수 외 다른 부분 동작 영향 없음 — diff 가 handleSave 내부로 한정
- 새로 점검 저장 시: photoKey 없는 경우 모든 cp에 undefined (현재와 동일)

**done:**
- handleSave 내 for 루프에서 cp 별로 keyForCp 가 분기되고, 한 계단실당 photoKey 가 정확히 1개의 record 에만 attach 됨
