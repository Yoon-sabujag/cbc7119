`functions/api/elevators/next-inspection.ts` 하나만 수정한다. 아래 6단계를 순서대로 적용할 것.

**(1) 타입 확장** — `ElevatorRow` 에 두 필드를 추가한다: `cert_no: string | null` 과
`cert_key: string | null`(하이픈 제거 정규화 키). 그 아래에 공단 이력 행 타입을 새로 선언한다 —
이름은 `HistoryRow`, 필드는 `elevator_no: string` / `inspect_date: string` / `valid_end: string | null`.

**(2) 1차 쿼리 SELECT 확장** — 기존 `elevators` + `elevator_inspections` LEFT JOIN 쿼리의
SELECT 목록에 `e.cert_no` 와 `REPLACE(e.cert_no, '-', '') AS cert_key` 두 항목을 추가한다.
`MAX(i.inspect_date) AS last_date` / `GROUP BY e.id` / `ORDER BY e.number` / LEFT JOIN 조건
(`i.type = 'annual'`)은 **1바이트도 바꾸지 말 것**. SQLite 의 `REPLACE(NULL, ...)` 는 NULL 을
반환하므로 cert_no 가 null 인 호기는 cert_key 도 자동으로 null 이 되어 매칭 대상에서 빠진다 —
별도 분기 불필요.

**(3) 2차 쿼리 + first-seen Map** — 1차 쿼리 `.all<ElevatorRow>()` 직후, `today` 계산 전에
공단 이력 쿼리를 추가한다. `SELECT elevator_no, inspect_date, valid_end FROM elevator_inspect_history`
에 `WHERE elevator_no IS NOT NULL AND inspect_date IS NOT NULL` 가드를 붙이고
`ORDER BY elevator_no, inspect_date DESC` 로 정렬해 `.all<HistoryRow>()` 한다.
`LIMIT` 은 붙이지 않는다(승강기 17대 규모의 회차 누적이라 전건이 수십~수백 행).

그 결과로 `officialMap` (`Map<string, HistoryRow>`) 을 만든다. 결과 배열을 순회하며
해당 `elevator_no` 가 Map 에 **아직 없을 때만** set 하는 first-seen 패턴을 쓴다 — 정렬이
`inspect_date DESC` 이므로 첫 등장이 곧 호기별 최신 1건이다. JS 쪽에서 날짜를 재비교하지 말 것.
Map 생성부 위에 한 줄 주석으로 "elevator_no 별 최신 1건만 = inspect_date DESC 정렬의 첫 등장"을 남긴다.

**(4) `.map(r => ...)` 안의 분기 재구성** — 핵심이다. 순서를 반드시 아래대로 할 것.

첫째, `cycleMonths = getCycleMonths(r.type, r.install_year, today)` 는 **기존 위치 그대로 맨 앞에서
항상 계산**한다(공단 경로를 타도 응답의 `cycleMonths` 필드가 비면 안 된다 — 참고 정보용으로 채운다.
단 공단 경로에서는 status 판정에 쓰이지 않는다).

둘째, 공단 이력 조회: `r.cert_key` 가 truthy 일 때만 `officialMap.get(r.cert_key)` 를 시도하고,
없으면 null 로 둔다(변수명 `official`).

셋째, 공단 경로 채택 여부를 판정한다. `official` 이 있고 그 `valid_end` 가 **truthy**
(null 뿐 아니라 빈 문자열도 거른다 — 불합격 등으로 공단이 유효기간을 안 준 경우)이며,
`parseISO(official.valid_end)` 결과가 유효한 Date 일 때만 채택한다. 유효성은
`Number.isNaN(parsed.getTime())` 이 false 인지로 확인할 것 — 공단 API 동기화로 들어온 외부
문자열이 비정상이면 `parseISO` 가 Invalid Date 를 돌려주고, 그걸 그대로 `.toISOString()` 하면
RangeError 로 엔드포인트 전체가 500 이 된다. 파싱 실패 시 조용히 폴백 경로로 내려갈 것.

넷째, `lastDate`(string | null) 와 `nextDate`(Date) 를 **두 경로 중 하나로만** 정한다:
  - 공단 경로 채택: `lastDate` = `official.inspect_date`, `nextDate` = 위에서 파싱해둔 valid_end Date.
  - 폴백(공단 이력 없음 / valid_end 없음 / 파싱 실패): `lastDate` = `r.last_date ?? null`,
    그 값이 있으면 `nextDate` = `addMonths(parseISO(lastDate), cycleMonths)`.

다섯째, `no_record` 조기 return 은 **두 소스가 모두 비었을 때만** 타게 한다 — 즉 공단 경로를
채택하지 못했고 `r.last_date` 도 없을 때. 반환 객체(필드 9종, nextDate/daysUntil null,
status `'no_record' as const`)는 **기존 코드 그대로** 유지할 것.

**(5) status 계산은 단일 블록으로 유지** — 이 플랜의 안전장치다. `differenceInDays(nextDate, today)`
와 `days < 0` → overdue / `days <= 90` → due_soon / else ok 판정은 **파일 전체에서 정확히 한 곳에만**
