# Quick 260711-39e — 라이브뷰 지연 개선 (LivePanelImage 자체 프리로드 폴)

## 배경 / 근거
- 라이브뷰 체감 5~6초. RCA: ① 에이전트 업로드 실질 ~2.75초 ② 앱 2단 폴(status 2초 → `frameUpdatedAt` → `latest.jpg`).
- **에이전트 주기 단축 불가** — R2 Class A write 무료한도 ~94% 경계(비용 0 목표). → 앱쪽만 개선.
- **staging-first 예외**: staging(cbc7119-data)에는 맥미니 프레임이 안 올라와 라이브뷰가 비어 육안 검증 불가 → 사용자 승인 하에 **prod 직접**.

## 변경 (프론트 1파일)
`src/components/panel/LivePanelImage.tsx` 만 수정 (소비처 6곳 무변경 — prop 시그니처 유지).
- 라이브 모드(`!snapshotKey`): status 의 `frameUpdatedAt` 대신 **자체 타이머(1200ms)로 `latest.jpg` 프리로드 폴**.
  - `new Image()` 로 다음 프레임 백그라운드 로드 → `onload` 성공분만 표시 src 교체(더블버퍼) → **깜빡임 0**.
  - `onerror`(204=프레임없음/네트워크) → 이전 프레임 유지 + 다음 폴 재시도. 연속 5회 초과 시 회색 placeholder.
  - `setTimeout` 체인(프리로드 완료 후 다음 예약 — 겹침 방지). unmount 시 cancel + clearTimeout.
- 경보 스냅샷 모드(`snapshotKey` 있음): 고정 URL, 자체 폴 없음(기존 동작 유지).
- `frameUpdatedAt` prop 은 초기 src + 하위호환용으로 유지.

## 효과 / 트레이드오프
- 2단 폴 → 1단. 지연 ~5-6초 → **~3-4초**(에이전트 업로드 ~2.75초가 남는 병목).
- `latest.jpg` 는 `Cache-Control: no-store` + ETag 없음 → 프리로드+표시 최대 2 fetch/frame. 라이브뷰 마운트 중에만·4인 내부·R2 Class B read 무료(월 1천만) 여유 → 무해. (필요 시 ETag/조건부요청 후속.)
- status 폴(2초)은 경보/신선도 라벨용으로 유지.

## 검증
1. `tsc && vite build` 성공.
2. 셀프 리뷰: setTimeout 체인 cleanup / 스냅샷 모드 폴 없음 / 프리로드 실패 시 이전 프레임 유지.
3. 배포 후 **사용자 육안 UAT**(실 프레임 흐름은 prod 에만): 라이브뷰 갱신이 빨라지고 깜빡임 없는지.
