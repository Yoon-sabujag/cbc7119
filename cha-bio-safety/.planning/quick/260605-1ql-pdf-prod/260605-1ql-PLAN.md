# Quick 260605-1ql: 식단표 PDF 파서 비정상 파싱 감지 가드 — prod 반영

## 배경

식단(weekly_menus) 데이터가 주중 공휴일로 PDF 한 열이 비면 이후 요일 메뉴가 한 칸씩
밀려 엉뚱한 날짜에 저장되던 사고(6/1~6/5 6/3 선거, 5/4~5/8 5/5 어린이날) 발생.
현재 파서는 헤더가 살아있는 케이스는 정상 처리하나, **깨진 파싱 결과가 정상 데이터를
조용히 덮어쓰는 것**을 막는 방어선이 없음. staging(cbc7119-data)에서 가드 구현·검증
완료(커밋 `dc981f0`) → 동일 변경을 production 에 반영.

## 적용 대상

`src/pages/StaffServicePage.tsx` — `handleMenuUpload` 함수, `const menus = colRanges...`
블록(현 396~405행) ~ `// 7) R2에 PDF 업로드` 사이. menus 생성 직후·`menuApi.upsert` 직전.

prod menus 블록이 staging "before" 와 정확히 일치 확인 완료(변수명 colRanges/holidayMap/
weekdayCols/collectTexts + `.filter(m => m.lunch_a || m.lunch_b || m.dinner)` 동일).

## Task 1 — 가드 3종 삽입 (staging dc981f0 verbatim)

- `extracted`(빈칸 필터 전, `dow` 포함) 추출 → `menus`(빈칸 필터 + dow strip)로 분리.
  upsert payload 는 기존과 동일(dow 미전송).
- 검증 ① 비-공휴일 평일(월~금)인데 중식A·중식B·석식 전부 공란 → throw(비는 날짜 표시)
- 검증 ② `menus.length < expectedDays`(평일·공휴일 제외) → throw(인식 일수 표시)
- 검증 ③ weekdayCols x 간격 한 칸이 중앙값 ~1.8배↑ → throw(헤더 누락 의심)
- 셋 중 하나라도 throw → 기존 try/catch 가 `toast.error(err.message)` 로 표시 + upsert 미도달.
- **files:** `src/pages/StaffServicePage.tsx`
- **verify:** `npx tsc --noEmit` PASS / `npm run build` PASS / grep 으로 3 가드 마커 존재
- **done:** 정상 PDF 통과 로직 무변경(빈칸 필터 보존), upsert 호출 payload 동일
